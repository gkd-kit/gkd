## 1 目标与边界

- 查询与 action 均有明确归属，支持请求取消、等待实际终止、拒绝迟到结果。
- 正确处理 TaskStack、无障碍事件和节点树更新顺序不一致，不仅依赖固定延迟猜测前台状态。
- 时间策略可配置、可记录、可在模拟环境验证。
- 开启调试后能解释当前阶段、耗时、规则成功或失败原因；关闭时不构造诊断记录，不增加节点读取。
- 用户可在应用内排查并导出；开发者和 AI 可通过同一协议查询、复现和分析。
- 不包装每个节点，不复制整棵节点树，不另建 Desktop 产品后端或共享空壳模块。
- 保留现有规则排序、优先级、共享次数和冷却、前置规则、延迟及重置语义。确需改变的行为单独列出并验证。

取消不等于回滚。已发生的触摸可能已经改变页面；同步 Binder 调用也不能保证立即返回。设计需要表达这些限制，而不是把协程终止统一表示为设备操作停止。

| --- | --- |
| commonMain 的 rule 领域 | 规则定义、运行状态、时间策略、协调器、工作身份、诊断数据及会话管理 |
| androidMain 的 a11y / priv | 平台事件转换、前台观察采集、真实节点访问、服务会话和真实输入 |
| jvmMain 对应功能包 | 模拟节点、模拟服务、可控输入结果，以及现有开发 HTTP 的诊断路由 |
| commonMain 的 ui | 两端共用的规则调试页、会话列表、运行时间线与导出流程 |
| scripts/desktop | 复用现有 TypeScript 工具入口，增加诊断和真机连接命令 |
| gkd-android 的 Debug 配置 | Debug 组件的 Manifest 注册 |

应用生命周期唯一持有执行协调器，协调器不依赖 ViewModel、Compose 或 Android Context。真实服务通过注册和解除注册提供能力；协调器只能在会话有效期间使用这些能力，解除后释放引用。

服务会话拥有节点访问能力和查询缓存。服务交接期间可以存在两个已连接服务，但只允许一个有效执行会话；旧输入未确认停止时，不允许新服务开始注入。

页面退出不停止后台协调器。应用结束、服务销毁分别清理自己拥有的任务与资源。测试通过正常构造和关闭独立会话隔离，不添加生产全局重置接口。

## 4 事件和节点的跨平台契约

### 4.1 共享事件表达语义

Android 先过滤和转换 `AccessibilityEvent`，再向共享核心提交所需信息。共享事件保留类型、App、可用的窗口标识、来源和接收时间，不复制 Android 的全部字段。

建议区分以下输入：

- 服务连接、断开和有效服务切换。
- 前台观察：TaskStack、窗口事件、实际节点读取。
- 内容变化：作为重新查询线索，可合并。
- 规则和设置变更：明确携带变更范围。
- 查询、输入和延迟任务的完成结果。
- 单次调试请求和取消命令。

来源观察不直接等于页面切换。Android 专属的 IME、系统窗口和组件过滤留在平台侧；共享核心处理归一后的身份关系和调度决策。

### 4.2 节点直接使用泛型

Android 使用 `AccessibilityNodeInfo`，模拟环境使用 `SimulatedNode`，复用 `gkd-selector` 的 `NodeAdapter<N>`。适配器按查询上下文持有，不为每个节点创建 wrapper，不建立镜像包装树。

泛型只贯穿来源节点、匹配和执行能力，不扩散到规则定义、诊断记录、数据库或 UI 状态。

事件来源节点延迟读取，避免被合并丢弃的事件提前触发 Binder 调用。若需要 `EventSource<N>`，只封装读取与释放契约；已有对象能承担职责时直接实现，不重复包装。Android 事件副本的获取和释放在实施时核对平台契约。

来源对象被消费、合并丢弃、会话关闭时都明确释放。候选节点只在所属工作内短期持有；日志保存必要的不可变信息，不持有节点。

### 4.3 查询缓存归属

查询工作独占可变遍历缓存；同一服务和页面内可沿用现有缓存策略串行复用，不允许迟到工作与新工作同时修改缓存。

读取根节点只返回结果，不顺便修改共享缓存。协调器确认结果有效后，所属查询才能接纳它。超时和取消不能保证中断 Binder，因此还需限制未结束的读取数量，避免每次超时都启动一个新阻塞调用。

节点树不是原子快照。即使工作身份有效，动作前仍需沿用必要的目标有效性检查；不能宣称版本标记能保证界面与输入原子一致。

## 5 前台观察与动态时序策略

### 5.1 不依赖固定来源优先级

| 来源 | 事实范围 | 限制 |
| --- | --- | --- |
| TaskStack | 任务和 Activity 变化线索 | 可能先于或晚于无障碍节点 |
| 无障碍窗口和状态事件 | 窗口或组件发生变化 | 不保证根节点已更新，也不都代表页面切换 |
| 节点读取 | 本次实际读取到的 App、窗口和节点 | 可能迟到，遍历期间也可能变化 |

每次观察记录接收序号、接收单调时间及可用的源时间。不同来源时钟不直接比较。识别器维护已确认执行上下文和待确认观察，并输出变更理由：

- 来源一致时接受变化。
- 新 TaskStack 指向 B、节点仍为 A 时，进入待确认，暂停旧上下文的新动作并复查。
- 节点先指向 B 时，不因迟到的 TaskStack A 直接回退；结合请求归属、窗口观察和后续确认决定。
- 失败或超时保持未知，不据此关闭权限、断开服务或修改用户设置。
- 通知栏、输入法、系统覆盖窗口与底层 Activity 可以不同，不做简单多数投票。

首次出现可能离开旧页面的有效冲突时，使旧候选失效并请求取消旧工作。待确认超时后维持明确的暂停原因，不自动把未知当成旧页面仍可执行。

App / Activity 相同不保证页面相同；普通 STATE_CHANGED 也不保证页面变化。第一阶段保留现有识别语义并集中实现，窗口身份和同 Activity 内页面边界通过具体场景逐步验证。

### 5.2 集中管理时间策略

建议用不可变策略快照统一配置：

| 参数类别 | 作用 |
| --- | --- |
| 内容事件合并间隔 | 降低重复查询，不丢失控制事件 |
| 前台冲突复查间隔与等待上限 | 等待观察收敛并给出超时原因 |
| 节点读取等待上限 | 限制调用方等待，迟到结果单独处理 |
| 页面变化后的补查窗口与间隔 | 处理事件先到、节点后到 |
| 动作后的补查窗口与间隔 | 观察输入后的界面变化 |
| 强制匹配唤醒间隔 | 保留 forced 规则行为 |

初始值从现有行为整理并记录依据，不凭经验一次性重调所有参数。规则的 matchDelay、actionDelay、actionCd 等保持独立，不纳入引擎调参。

通过显式命令更新策略并分配版本。查询启动时固定策略；更新后重算尚未触发的引擎唤醒，不修改已开始手势的时长。临时诊断参数默认只属于会话，不悄悄写入生产设置。

第一版实现运行时可配置和可观测，不自动学习延迟。后续根据不同来源的实际到达差分和查询结果评估自适应策略，并设置上下界。

调度和耗时使用单调时间，记录日期使用墙上时钟。现有规则时间字段迁移前核对是否存在持久化或外部依赖，不能直接替换所有时间来源。

## 6 统一调度与规则状态

### 6.1 协调器串行决策

协调器串行处理短事件，不在事件处理函数中执行 Binder、节点遍历、文件写入或等待输入停止。耗时子任务完成后回传结果。

控制事件保留顺序和语义；高频内容事件按会话合并。待处理内容变化只表示“需要重新查询”，不生成无限查询队列。控制入口与内容合并状态之间定义统一接收顺序，避免内容积压饿死取消命令。

初始并发约束：

- 每个有效服务会话最多一个有效查询。
- 全应用最多一个执行中或等待停止的输入。
- 动作期间继续处理页面、服务和设置变化；普通内容更新合并到下一轮。
- 不排队保存多份候选节点。动作结束后重新查询。
- 旧任务逻辑失效后仍可能物理运行，资源回收必须等实际结束；其结果不再进入新上下文。

单次工作携带服务会话标识、执行上下文版本和规则版本。它们分别解决服务交接、页面变化和规则变更，不把每个普通内容事件都当成整个上下文失效。

### 6.2 规则定义与运行状态

不可变定义包含编译后的 selector、参数、排序与规则身份；运行状态包含次数、冷却、延迟和前置触发关系。协调器负责运行状态修改，匹配工作读取固定输入并返回结果。

保留 actionMaximumKey、actionCdKey 的共享关系，以及 App、Activity、Match 三种 resetMatch 语义。规则重建后如何对应旧状态沿用现有策略，迁移时用测试明确，不能靠对象引用偶然保持。

统一维护待查询原因、规则到期任务和最近一次引擎唤醒。规则延迟到期重新评估并重新匹配，不直接执行旧节点。替换多个 300 ms 补查任务时保留既有触发窗口和优先级。

高优先级抢占只取消或重排查询，不直接打断已经提交的输入；若将来需要输入抢占，单独定义业务语义。

## 7 action 生命周期与取消

动作经历准备、执行、请求取消、实际终止几个阶段。阶段名称用于表达不同事实，不将 CancelRequested 等同于 Cancelled。

| 变化 | 查询处理 | 动作处理 |
| --- | --- | --- |
| 有效服务切换或销毁 | 取消并拒绝迟到结果 | 立即请求停止，不等待原有交接延迟 |
| 确认页面变化或有效前台冲突 | 使候选失效并重新确认 | 取消旧上下文动作 |
| 普通内容更新 | 合并，按查询策略处理 | 不取消，避免手势自取消 |
| 关闭匹配或自动化 | 停止所属自动查询 | 取消所属自动动作 |
| 当前规则关闭或移除 | 丢弃对应候选 | 请求停止对应动作 |
| 无关规则变化 | 更新后续查询 | 不必取消当前动作 |
| 取消单次调试任务 | 取消该任务 | 不影响其他正常工作 |

取消由协调器发起，子任务完成清理后通知终止。协调器本身不阻塞执行 cancelAndJoin；清理确认前保持输入占用。

特权输入取消协程后由 PrivilegeInput 尝试释放触摸；同步 Binder 返回前可能不能完成取消，DeadObject 等错误按库契约处理。

无障碍 dispatchGesture 改为等待 GestureResultCallback，不再用固定 delay 推断完成。取消调用方并不撤销系统手势；在确认回调或平台明确终止前保留输入占用。如果无法确认，报告状态未知，不通过超时伪造停止。

无障碍滑动的连续短段与结束触摸已实现，Android 13 的连续性和取消收尾验证见第 18 节。取消等当前短段回调，再在已到达位置结束同一个触点，不用额外点击充当取消；仍不承诺立即停止或跨设备硬时限。

动作开始时固定规则、页面及记录所需信息。结束后：

- 已确认成功的动作可记录到原执行上下文。
- 旧上下文结果不能修改新页面重置后的规则状态。
- 取消不记作成功，不触发失败回退重放。
- 取消请求与完成回调竞态通过单一终止结果处理，避免重复记数。
- 明确区分执行事实的历史记录与当前规则状态推进，不能因页面随后变化抹掉已经完成的动作。

HTTP 单次执行和正常规则动作使用同一输入调度入口。手动匹配不执行；请求执行时明确指定是否暂停正常自动任务，不允许静默并发注入。

## 8 按需实时诊断

### 8.1 会话与记录

调试开启后创建有限时长、有限容量的诊断会话，固定规则内容及版本、环境、策略版本、调试级别和允许操作范围。

记录关联 sessionId、queryId、ruleId、actionId，以及服务和执行上下文身份。每条事件包含递增序号、单调时间、实际日期、阶段、稳定原因代码和必要字段；界面用 Compose Resources 解析说明，日志保留机器可分析的原因代码。

| 阶段 | 必须能够解释的内容 |
| --- | --- |
| 接收与合并 | 哪个来源触发，哪些内容事件被合并或过滤 |
| 前台识别 | 各来源观察、冲突、采纳和丢弃理由 |
| 调度 | 为什么未启动、等待什么、下一次唤醒时间 |
| 节点读取 | 排队、读取耗时，超时和迟到结果 |
| 规则资格 | 页面条件、次数、冷却、前置规则、匹配时间和延迟 |
| selector 匹配 | 必要条件未命中、anyMatches 全部失败、排除条件命中 |
| 动作 | 目标归属、执行方式、开始、取消请求及最终结果 |
| 结果处理 | 是否接受，是否因会话或规则变化而丢弃 |

耗时区分排队、平台读取、匹配和输入；嵌套耗时不能简单相加。基础流程不额外读取节点。详细 selector 解释优先增加实际匹配过程的可选观测点，不能为了日志重新执行一次匹配。

### 8.2 级别与性能

| 级别 | 行为 |
| --- | --- |
| 关闭 | 无诊断事件构造、格式化、耗时采样、节点额外读取或诊断刷新任务 |
| 流程 | 阶段、原因、规则结果、耗时、异常及取消 |
| 指定规则详细 | 有限的 selector 和节点访问细节，限制规则范围、数量和时间 |

正常错误日志与生产业务记录保持原职责，不受“关闭诊断”影响。关闭时允许少量入口判断，不承诺绝对零指令开销。

不能先格式化再调用空 logger。诊断关闭时不创建昂贵参数或闭包；详细匹配路径在工作入口选择，避免每个节点执行复杂开关判断。

诊断记录写入有界缓冲区，文件导出和流客户端消费在工作路径外执行。容量不足明确记录缺口及丢弃量，不能阻塞引擎。停止或到期后解除采集；已保存记录按保留策略管理。

调试会话不等于执行会话。停止观察不停止正常自动化；若会话拥有单次执行任务，结束时明确取消这些任务并等待清理。

### 8.3 用户界面

共享调试页面直接订阅诊断来源，不经 HTTP 绕行。提供：

- 当前服务、页面判断及冲突。
- 当前阶段、规则、selector、待查询原因和下一次唤醒。
- 运行列表及成功、失败、取消筛选。
- 详细时间线和原始结构化记录。
- 规则快照、调参、停止采集及导出。

当前耗时由 UI 根据阶段开始时间计算；引擎只发布阶段变化，避免高频广播。时间线批次更新，业务状态由所属 ViewModel 持有，通用组件只接收状态和事件。

“未查询”“不具备执行条件”“未匹配”“结果过期”“执行失败”分别展示，不统一称为匹配失败。

## 9 诊断 API 与 SSE

commonMain 提供诊断命令和查询服务；HTTP 只是平台传输适配，不新建第二套状态。

| 建议接口 | 用途 |
| --- | --- |
| POST /debug/sessions | 创建诊断会话，指定规则和级别 |
| POST /debug/sessions/{id}/runs | 单次匹配或明确执行 |
| POST /debug/sessions/{id}/runs/{runId}/cancel | 请求取消指定任务 |
| GET /debug/sessions/{id} | 当前阶段、耗时起点与工作状态 |
| GET /debug/sessions/{id}/events?after={seq} | 分页增量读取 |
| GET /debug/sessions/{id}/stream | SSE 实时订阅 |
| POST /debug/sessions/{id}/stop | 停止采集并处理会话拥有的任务 |
| POST /debug/sessions/{id}/export | 创建诊断包 |

控制操作使用普通 HTTP，实时单向日志使用 SSE，无需仅为这些操作引入 WebSocket。分页和 SSE 读取同一份记录。

SSE 使用事件序号作为 id，重连按 Last-Event-ID 或游标补读。记录已被覆盖时返回明确缺口；不将连接断开当成停止诊断。订阅初始化以同一来源的游标和快照建立边界，避免先读取历史再订阅时遗漏中间事件。

创建执行任务需要请求标识；客户端超时后先查询原任务，不能盲目重发导致重复输入。此保护限定在有副作用的执行请求，不为所有只读接口增加复杂协议。

## 10 Debug 真机调用入口

建议路径为：TypeScript CLI → ADB 指定设备及端口转发 → Android Debug 本机 HTTP → 共享协调器和诊断会话。

仅一个 Debug 专用启动入口负责启动、查询连接信息和停止调试服务，不为每个操作注册 exported 组件。诊断接入实现放在 gkd-app 的 androidDebug，由 gkd-android 的 Debug 源集编译并通过 Debug Manifest 装配到统一 DebugService。诊断与浏览器接口共用配置端口，Android 支持局域网访问；诊断接口要求短期 Bearer 凭据，Release 不装配诊断路由。

启动过程生成短期会话凭据，HTTP 全部校验。ADB 转发与 localhost 绑定本身不替代鉴权；启动入口本身也不能是任意应用均可无授权启动并取走凭据的入口。实施前验证 shell 授权方式及凭据交付渠道，凭据不写普通日志。

生命周期要求：

1. 指定设备，查询是否已有可复用的诊断服务。
2. 启动并等待明确 Ready，取得连接信息和会话凭据。
3. 建立本次所有的 ADB 转发，再做健康检查。
4. 发起诊断或单次任务；动作必须走生产协调器。
5. 结束时停止所属会话，恢复本次临时字段，撤销本次转发。
6. 进程终止或断连后保留恢复信息，下次连接先核对未完成恢复，不覆盖其他用户设置。

Android 入口由统一 DebugService 承载；服务实现位于 androidMain，诊断接入位于 androidDebug。Debug Manifest 为同一组件启用受权限保护的 ADB 入口，Release 不导出服务。

开放有限命令，不提供任意脚本、反射或文件读写。界面交互通过真实控件完成，不能用直接修改业务状态冒充点击。

真机检查遵守现有自动化开关和运行模式的记录、暂停及 finally 恢复要求。观察真实自动化运行需明确授权的诊断模式和范围，并在启用前处理其与当前规则的关系，不作为默认例外。

## 11 CLI 与用户排查流程

沿用 `pnpm app-tools` 和根 scripts/desktop。命令示意：

```text
pnpm app-tools device debug start --serial <设备>
pnpm app-tools debug start --rule <规则标识>
pnpm app-tools debug match --session <会话>
pnpm app-tools debug status --session <会话>
pnpm app-tools debug events --session <会话> --after <序号>
pnpm app-tools debug watch --session <会话> --duration 20s
pnpm app-tools debug cancel --session <会话> --run <任务>
pnpm app-tools debug export --session <会话>
pnpm app-tools device debug stop --serial <设备>
```

命令输出默认简短摘要，支持 JSON。watch 有时间上限，适合 AI 工具调用；常规排查使用状态查询和增量记录，不持续拉取整份日志。Desktop 与真机仅连接方式不同，诊断操作复用同一客户端。

给定规则调试分为：观察正常运行、单次完整匹配、单次匹配并执行。单次匹配默认无输入副作用，不改变正常规则计数和冷却；“只测 selector”作为独立功能标明绕过了哪些规则条件。

用户在规则页启动诊断、复现、查看摘要和时间线、停止并导出。AI 可完成同一流程，必要时再针对指定规则提升诊断级别。

诊断包包含规则快照、应用和平台版本、策略、结构化事件、摘要及记录缺口。截图、节点树和界面文本为显式附加采集，导出前展示包含范围。凭据和不必要的敏感设置不进入诊断包。

日志并不等于完整可重放输入。需要确定性复现时，额外保存明确的模拟观察、节点树和输入结果序列，不能仅凭日志声称还原了真实系统。

### 验证矩阵

- 前台顺序：TaskStack 先到、后到、迟到旧结果；系统覆盖窗口；同 Activity 状态变化。
- 查询：内容突发、高优先级抢占、慢节点读取、超时后迟到、关闭服务时遍历未结束。
- 规则：共享次数和冷却、前置规则、三种 resetMatch、actionDelay 后重新匹配。
- 输入：长滑动中切页面、服务交接、取消后立即执行、取消和成功同时到达、Binder 断连。
- 诊断：关闭与开启产生相同业务决策，缓冲覆盖和 SSE 重连有缺口说明，慢订阅者不影响执行。
- 性能：对同一节点树和规则比较总耗时、节点访问数、缓存命中及分配；分别测关闭、流程和详细级别。
- 真机入口：认证失败、重复请求、进程退出、端口转发失败、恢复中断及 Release Manifest 不注册入口。

共享调度和模拟逻辑用 JVM 测试与可控协程时钟；平台取消、事件生命周期、Binder 和手势连续性按需真机验证。修改隐藏 API、remap 或相关依赖时按专项技能验证 gkd Release 最终 R8 输入和 DEX。验证任务不得关联未授权上传。

## 18 无障碍连续滑动与快速取消（2026-10-21）

已将无障碍 swipe 从一次性长 StrokeDescription 改为 100 ms 连续段。分段顺序、整数坐标插值、静止等待及不可取消收尾在 commonMain `continuousSwipe`；Android 适配层只构造/续接 StrokeDescription 并等待回调。特权输入继续使用 priv-kit input，点击和长按保留原有完整手势回调等待，不因为这次滑动改造而重放或改用其他后端。

取消过程为：当前已提交段返回 → 停止产生后续移动段 → 从当前已到达的点续接 1 ms 原地结束段 → 等收尾回调 → 原取消继续传播。分段完成并不代表触点已抬起，因此 held stroke 在回调后仍被保留。结束段沿用同一个触点，不发起额外 DOWN。Android 不为相同整数坐标生成 MOVE，空续段可能失败；这类区间改为可取消等待，避免原地长按和 1 像素慢滑动被错误拆成空续段。

执行协调器也补上收尾错误传播：调用方取消后先等待内部任务结束，再检查结果；若结束段被拒绝或清理抛出非取消异常，不再用原 CancellationException 掩盖错误。收尾未确认会报告失败，不声称触点已释放；系统不回调仍继续等待。100 ms 是分段预算，不是硬取消时限。结束触点使用 UP，并非向目标应用发送 ACTION_CANCEL，无法撤销已经发生的滚动、长按、点击判定或惯性。

新增仅 Debug 注册且要求 INTERACT_ACROSS_USERS_FULL 权限的 `GestureDebugActivity`，实现位于 androidDebug。它消费所有触摸、没有可点击控件，通过现有认证调试服务导出真实 MotionEvent；生产窗口不增加触摸监听。`device-gesture-check` 使用原有生产规则/ActionPerformer/协调器执行，核对 `shell=false`，不直接调用一份测试滑动实现。命令与事件检查说明见 [调试文档](matching-engine-debugging.md#无障碍连续滑动与取消验证)。

| 场景 | 请求时长 | 实际 DOWN→UP | 取消请求到协程终态 | 请求前采样到实际 UP |
| --- | --- | --- | --- | --- |
| 正常跨段滑动 | 1200 ms | 1239 ms | — | — |
| 首段取消 | 4000 ms | 103 ms | 58 ms | 32 ms |
| 中途取消 | 4000 ms | 522 ms | 125 ms | 114 ms |
| 原地保持 | 400 ms | 402 ms | — | — |
| 1 像素慢滑动 | 450 ms | 453 ms | — | — |
| 原地保持取消 | 4000 ms | 308 ms | 14 ms | 11 ms |
| 三次取消后的短滑动 | 每次 250 ms | 256 / 255 / 257 ms | — | — |

## 23 Perfetto 补验、剩余项核对与断连诊断（2026-10-21）

### Binder 数据与工具补齐

当前 Android 13 / M2012K11AC 上分别采集全树不命中、文本快速查询不命中、根节点命中，三种缓存策略 × off/flow/detailed，每组预热 2 次、测量 8 次。三份 trace 共 216 次正式查询、528 个同步测量区间、504 个 Binder 事务，全部区间与节点计数匹配，无未结束/跨界事务，无 trace 错误或丢失。最终 Debug APK 又重采了全树场景。

| 场景 | Cold 每次事务 | Warm 每次事务 | RefreshRoot 每次事务 |
| --- | --- | --- | --- |
| 全树不命中 | 2 | 1 | 4 |
| 文本快速查询不命中 | 2 | 2 | 3 |
| 根节点命中 | 2 | 1 | 4 |

每个场景的三档诊断计数一致，未发现额外 Binder 事务。结果只覆盖同线程正式测量区间，不等于所有进程工作，也不把 Android 框架缓存当作 GKD 缓存。三份实测 trace 没有单向事务；受控 Trace Processor 输入另行验证了单向事务只计数、不混入同步耗时。开启 trace 会扰动时延，本轮用来补齐事务证据，不设置跨设备时间预算。

新增 `matching-binder-summary`：使用官方 Trace Processor 执行仓库 SQL、输出结构化报告，并核对区间覆盖、进程、事务边界及错误/丢失；缺失测量区间不能默认为零事务，失败仍保留报告。SQL 明确排除单向事务的同步耗时，嵌套读取按最内层归属。受控 trace 验证嵌套去重、预热排除、单向耗时排除及截断拒绝，命令见调试文档。

设备恢复同时修复 Android 组件名规范化的比较：`package/package.Service` 与 `package/.Service` 是同一成员，不再因这种改写跳过原全局无障碍开关的恢复；真实新增的其他服务仍保留。工具测试覆盖原开关为 0 的规范化场景及断连/用户新增服务场景。

### 当前设备的边界验证

- 自由窗口：ADB 确认 GKD 任务的 `mode=freeform`，生产根节点查询通过，随后恢复 fullscreen。MIUI 仍给出全屏大小边界，没有证明两个实际并排窗口的焦点切换；完整分屏矩阵仍保留。
- 强制服务断开：在 4 秒 A11y 连续滑动中移除 GKD 无障碍服务。测试窗口收到 ACTION_CANCEL，`down=false`；但应用手势回调未到，8 秒观察后执行通道仍被旧任务占用，系统录制未封口。这是平台回调与物理触点证据不同，不能报告普通取消成功或整包回放通过。
- Android 13 源码核对：`AccessibilityService` 的 `DO_GESTURE_COMPLETE` 只在连接 ID 有效时交付回调，断连后的回调可被忽略；`MotionEventInjector` 的触点取消和通知也属于另一条异步链。Service 销毁不提供应用可等待的释放确认。源码通过 android-api-diff 读取并保留，未据单台物理 CANCEL 推导跨设备保证。
- 已补齐可操作的诊断：引擎快照公开 `cancelling`，页面/服务等系统触发的取消同步反映到单次请求状态；就绪检查区分 `platform_cleanup_pending` 和 `service_disconnected_cleanup_unconfirmed`。页面与离线摘要提示导出证据及必要时重启应用；不会自动超时放行、新建输入抢占或把重启当作旧动作成功。读取请求状态时不在请求锁内读取协调器，避免与停止诊断的锁顺序相反。

## 24 职责与依赖复核（2026-10-21）

本轮检查实际导入与调用链，保留职责包结构，不新建 Gradle 模块。已调整的边界如下：

- `RuleRuntime`、`RuleExecutionState`、规则延迟类型、状态快照与稳定规则身份归入 `rule`。领域层声明可选 `RuleStateObserver`，系统录制器实现它；`rule` 不再依赖 `matching` 或具体录制器，关闭录制时不创建状态快照。
- `MatchingRuntime` 不再引用 `MatchDebugRuns`。协调器持有诊断会话的子协程生命周期，调试入口取得该会话作用域；停止、过期和应用关闭取消所属请求，取消沿现有执行通道等待动作收尾。停止会话不会取消普通自动匹配。会话取消在协调器锁外触发，避免请求完成回调反向取得请求锁。
- 选择器组合算法不再引用具体诊断解释器或录制计划。属性解释在 diagnostics 组装，录制计划在 replay 解释，两者复用同一组合算法；输入算法中的无用 replay 导入已删除。Android 查询显式接收诊断对象，不隐式读取全局会话。
- 调度状态机不再接受录制专用的 `rule_state` 空操作，也不引用诊断 DTO。系统录制 `version: 2` 的每一步分别保存调度命令或规则观察，回放校验二者互斥，并拒绝规则观察携带调度效果。旧开发录制需重新采集，不增加旧格式适配；生产规则、设置和组件标识未变。

保留的直接协作有实际一致性要求：协调器记录真实调度顺序；`queryRules` 通过 `MatchWork` 共用取消、提交与动作边界；Android 前台身份与规则快照在同一锁内更新。`AndroidMatchHost` 仍负责组装平台输入、查询与动作。这些关系没有为了消除所有包级环而增加转发接口。当前职责与依赖说明已同步到 architecture.md。
